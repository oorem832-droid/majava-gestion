# MAJAVA — Rental management system (Supabase version)

Files in this folder:

| File | Purpose |
|---|---|
| `01_schema.sql` | Tables, roles, row-level security, server-side double-booking check |
| `02_catalogue_et_demo.sql` | The 223 real catalogue articles + **fictitious** demo data (prices, stock, clients, rentals) |
| `index.html` | The application (French UI, login screen, 4 roles) |
| `config.js` | Your Supabase URL and public key |

## Set-up (about 30 minutes)

### 1. Create the database
1. Create a free project at supabase.com (note the database password somewhere safe).
2. Open **SQL Editor**, paste `01_schema.sql`, click **Run**.
3. Paste `02_catalogue_et_demo.sql`, click **Run**. (For production keep only the PRODUCTS block, see below.)

### 2. Lock down who can sign in  ⚠ important
1. **Authentication → Sign In / Providers → Email**: keep Email enabled and **turn OFF "Allow new users to sign up"**. Otherwise anyone who finds the page could create an account and read the data. (Menu names change occasionally; look for the sign-up toggle.)
2. **Authentication → Users → Add user**: create the **owner/admin first** (tick "Auto confirm user"). The first account created automatically becomes **Administrateur**.
3. Add the other staff the same way. They start as **Caissier(ère)** (minimum rights). The admin then opens **Équipe & accès → Modifier** in the app to set the right role.

### 3. Connect the app
1. **Project Settings → API**: copy the **Project URL** and the **anon public** key into `config.js`.
2. Never paste the `service_role` key anywhere in this folder.

### 4. Publish
Upload the folder (`index.html` + `config.js`) to any static host: Netlify (drag & drop), Vercel, Cloudflare Pages or GitHub Pages. Open the address, log in with the admin account.
Open it once from your own computer first (double-click `index.html`) to check the connection.

### 5. Test checklist
- [ ] Log in as admin; the dashboard shows the demo rentals.
- [ ] Create a rental, confirm it, mark it out, record a return with 1 broken item. Refresh the page: everything is still there.
- [ ] Open the app in two browsers and try to confirm two rentals needing the same chairs on the same date: the second must be refused.
- [ ] Log in as a cashier: no Reports / Team / Stock-movement menus, no "Ajuster" buttons.
- [ ] Try to open the page logged out: only the login screen appears.

## Going from demo to production
1. Delete the demo blocks (clients, suppliers, rentals, purchases, moves) from `02_catalogue_et_demo.sql` before running it, or clear those tables afterwards.
2. Replace prices (`price`), stock (`stock`), alert thresholds (`min_stock`) and costs (`cost`) with MAJAVA's real figures, then do a physical stock count and enter it with **Ajuster le stock**.
3. Use a **custom domain** and HTTPS (included on the hosts above).
4. Check Supabase's current plans for **automatic backups** and project pausing rules, and pick a plan accordingly. Test a restore once.
5. Move product photos out of `index.html` into Supabase Storage when you have the original files.

## What was tested, and what was not
- ✅ Schema, security policies, triggers and demo data: run on a real PostgreSQL 16 with a stand-in for Supabase Auth. Verified: role permissions, double-booking refusal, immutable stock journal, no access when logged out.
- ✅ Front end: all flows (login, rentals, outings/returns, payments, staff, roles, error rollback) against an in-memory stand-in for the Supabase API.
- ❌ **Not tested against a real Supabase project.** Run the checklist above first; small differences (e.g. dashboard setting names) are possible.

## Known limits of this demo version (planned for production)
- Document numbers (LOC-…, ACH-…) are generated by the browser; two people creating at the same second could collide (the second gets a "retry" message). Production: numbering in the database.
- A return touches several tables in separate calls, not one transaction. Production: a database function doing it atomically.
- Status changes (out / return) are restricted to the right roles in the interface; the database only checks that the user is an active staff member. Production: enforce in the database too.
- Lines, payments and losses are stored as JSON inside the rental. Fine for reporting at this size; production can normalise them.
- No real-time push: data refreshes every 45 seconds and via "Actualiser les données".
- Password reset is done from the Supabase dashboard (no in-app screen yet).
- Printing invoices uses the browser's print dialog (save as PDF); server-generated PDFs are a production item.
